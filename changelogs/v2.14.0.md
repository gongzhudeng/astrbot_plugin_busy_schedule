# v2.14.0

- 日程生成上下文大换血：新增 `{attention_context}`（内心世界待关注事项：用户提过的约定与要求，持久挂起直到完成，第二天生成时依然在场，约定不再因聊天轮数滚动而丢失）与 `{recent_memories}`（长期记忆插件最新的普通记忆，默认 2 条，单条 500 字可配；别名 `{memory_context}`）。
- 近期记忆自动排除"整合记忆"：零点记忆整合产出的跨周/跨月长期摘要（metadata 带 consolidated_at 标记）永不注入，不挤占条数预算——配合 livingmemory 2.7.0-gd.7 的接口过滤，日程修正侧同步受益。
- 知识库/记忆检索（RAG）默认关闭：原"拿最近几轮对话当检索词"的方式检索窗口天然短视，已被「待关注事项 + 近期记忆」取代。开关保留，开启后仅当模板中写了 `{rag_context}` 才生效；默认模板已移除该段。
- 新增配置：「日程生成」组的待关注事项条数上限（默认 5）、近期记忆条数上限（默认 2）、单条记忆字数上限（默认 500）。
- 默认模板更新：「相关记忆与知识」段替换为「待关注事项」+「近期记忆」两段，信息优先级句同步纳入待关注事项；待关注事项段内注明"与今天无关的事项（长期愿望、明天及以后）不排进今天日程"。
- 自定义模板兼容：`{rag_context}` 占位符代码保留，旧模板不受影响；`{attention_context}`/`{recent_memories}`/`{memory_context}` 均可在生成模板中自由使用。
