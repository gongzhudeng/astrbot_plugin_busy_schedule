# v2.14.13

日程修正不再出现"改一半"：整批校验 + 关键词删除放行 + 联动规则补强。

## 背景（10-12 13:20 事故）

修正日程把"买菜做大餐"和"点外卖/吃外卖"两套安排同时留在了日程里，且买菜与取包裹被挤进同一小时。查日志发现**模型这次完全做对了**——它给出 5 条正确的联动操作，是代码把其中 3 条拒了：

| 模型操作 | 结果 | 拒绝原因 |
|---|---|---|
| update 15:41 → 取包裹+顺路买菜+拍视频 | 应用 | — |
| update 17:26 点外卖 → 备菜下厨做大餐 | 应用 | — |
| remove 17:58 取外卖 | **拒绝** | 命中 `IMPORTANT_ACTIVITY_KEYWORDS` 里的"外卖"，被判"重要活动需确认"跳过 |
| update 18:21 吃晚饭 → 18:35 吃自己做的 | **拒绝** | 上一条没删掉 → `activity overlaps the previous activity` |
| update 19:07 补番 → 19:25 | **拒绝** | 同上，连带失败 |

之后代码的**逐条降级**兜底把结果固化成了半成品：前两条生效、后三条丢弃 → 新旧两套安排并存。

## 改动

### 1. 整批失败不再降级为逐条（`core/corrector.py`）

删除 `_apply_per_operation` 逐条兜底。联动修正在整体上才构成合法时间线，只应用子集必然留下错位的半成品日程。现在批量不通过就**整批放弃**，返回"操作未通过校验，日程保持原样"。

### 2. 自动修正放行关键词命中的删除（`core/corrector.py`）

`editor.apply(..., confirmed_important=True)`。原默认 `False` 在这条链路上**没有任何生效可能**——定时修正是无人值守任务，没人能应答确认弹窗，命中关键词只会变成静默跳过。`IMPORTANT_ACTIVITY_KEYWORDS` 保留给手动 `edit_current_schedule` 链路使用（那条路有 `mode="check"` 预检 + `confirmed_important` 参数，是完整的设计意图），本次不动。

### 3. 提示词补三条联动规则（`_CORRECTION_RULES_SUFFIX` + `_conf_schema.json` 默认值 + 用户配置副本，三处同步）

- **6.1 新事项独立成条**：用户新提出的约定若含具体动作（买菜、取件、做饭、运动、出门等），必须作为独立活动写入，不许塞进现有活动描述、不许与别的活动并条——日程要能看出她此刻在哪一步。
- **6.2 新计划顶掉旧安排**：新事项与已有活动功能重叠时（在家做晚饭 vs 点外卖），必须 remove/改写旧的并顺延后续；**不允许新旧两套安排并存**。
- **6.3 一次改到位**：联动修改的 remove/update/add 全部写进同一批 operations；这批操作整体校验，任一条不合法则整批不生效。

未采用"活动时长参考表"——用户判断给了会太死板，靠规则约束即可。
