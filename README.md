# 灵犀 · AI忙碌时段管理插件

> 作者：灵犀 | 仓库：[astrbot_plugin_busy_schedule](https://github.com/gongzhudeng/astrbot_plugin_busy_schedule) | 主页：[gongzhudeng](https://github.com/gongzhudeng)

让AI拥有真实的生活节奏，不再是一个24小时在线的机器人。

## 功能特性

### 核心功能
- **智能忙碌时段计算**：根据日程安排自动计算一天的忙碌时段
- **消息拦截合并**：忙碌时段内的消息会被拦截并合并，忙完后统一处理
- **提前通知**：进入忙碌前会提前告知用户，避免突然消失
- **特殊关键词唤醒**：支持设置关键词让AI立即响应
- **聊天保护**：主对话模型刚完成有效回复或主动对话模型刚发起请求时，不会立刻进入忙碌状态
- **动态日程调整**：可选功能，根据聊天上下文动态调整忙碌时段

### 日程生成
- 每日自动生成穿搭和日程安排
- 每个活动标记忙碌状态（可回消息/不可回消息）
- 支持创意池随机选择，增加多样性
- 历史日程参考，避免重复
- `忙碌日程` 和 `忙碌状态` 以本地图片展示；支持自动、白天和夜间主题，渲染失败时回退到文字

### 提示词注入
- 正常和忙碌请求都按固定顺序写入 `system_prompt`：AstrBot 人设、日期/星期/农历/节日、今日穿搭、今日天气、今日日程、自定义提示、下一个/当前活动、忙碌状态、内心世界锚点、执行记录；日期信息与穿搭、天气、日程位于同一个稳定的 `<character_static>` 块中
- 日期上下文支持三种注入模式：始终注入（平时只显示公历日期、星期、农历，有节日或特别日才追加）、仅在有节日或特别日时注入、完全关闭；旧版布尔开关仍兼容
- 穿搭、天气和日程作为每日稳定块；活动、忙碌状态和执行记录分别独立更新
- 忙碌状态块只表示当前忙碌，不重复活动名称；内心世界插件通过锚点插入到忙碌状态与执行记录之间
- 普通请求不再把日程和动态状态追加到 user 尾部
- 延迟消息正文只进入本轮真实 user 内容一次；接收时间、忙碌活动和处理时间只进入临时唤醒上下文，不写入聊天历史

### 自定义特别日

在“日程生成”配置中添加特别日规则，可使用指定日期（`YYYY-MM-DD`）、每年某月某日、每月某日或每周某天，并填写名称、备注和优先级。命中规则会同时进入日程生成提示词和普通对话提示词；修改后可使用“忙碌重写”立即生成当日日程。

## 使用方法

### 命令列表

| 命令 | 别名 | 说明 |
|------|------|------|
| `忙碌日程` | `busy show` | 以图片查看今日日程和忙碌时段 |
| `忙碌重写` | `busy renew` | 重写今日日程（可附加补充要求） |
| `忙碌状态` | `busy status` | 查看当前忙碌状态 |
| `忙碌帮助` | `busy help` | 显示帮助信息 |

### 配置项

#### 基础设置
- **启用插件**：总开关
- **日程生成时间**：每日生成日程的时间（默认 07:00）
- **LLM供应商**：指定生成日程和计算忙碌时段的LLM

#### 图片显示
- **自动切换**：07:00-18:59 使用白天主题，其余时间使用夜间主题，按 AstrBot 全局时区判断
- **白天模式 / 夜间模式**：固定使用指定主题
- 图片头像每次从插件目录的 `logo.png` 读取，替换同名文件后下一次命令自动更新

#### 忙碌时段设置
- **提前通知时间**：进入忙碌前多少分钟通知用户
- **聊天保护时间**：指定对话模型活动后多少分钟内不进入忙碌；用户消息、斜杠命令和后台模型不刷新
- **唤醒后冷却时间**：被关键词唤醒后多少分钟重新计算忙碌

#### 睡眠设置
- **基础睡眠时间**：默认睡眠时段（如 23:00-07:00）
- **动态睡眠调整**：根据用户聊天情况动态调整睡眠时间
- **无消息睡眠阈值**：用户多少分钟没消息可以进入睡眠

#### 关键词设置
- **唤醒关键词**：触发立即响应的关键词列表
- **匹配模式**：包含模式 / 完全匹配模式

#### 消息合并设置
- **最大消息数**：达到此数量立即发送合并消息
- **延迟发送时间**：最后一条消息后多少秒发送

#### 动态调整设置
- **启用动态调整**：是否根据聊天上下文动态调整忙碌时段
- **调整冷却时间**：两次调整之间的最小间隔

## 提示词注入说明

### system_prompt 固定顺序
```
AstrBot 人设
<character_static>
## 今日穿搭
## 今日天气
## 今日日程安排
</character_static>
<character_custom>...</character_custom>
<character_activity>下一个活动 / 当前活动</character_activity>
<character_busy>## 当前处于忙碌状态</character_busy>
<!-- EMOTION_STATE_ANCHOR -->
<character_execution>...</character_execution>
```

### 延迟消息唤醒上下文
```
<busy_schedule_wake_context>
这些是你在忙碌时段（[开始时间]-[结束时间]）收到的用户消息：
消息正文已作为本轮 user 内容提供；此处不重复正文。
实际接收时间区间：[完整 ISO 时间] 至 [完整 ISO 时间]
本轮实际处理/回复时间：[完整 ISO 时间]
AstrBot 的 Current datetime 与处理时间代表真正回复时刻；接收时间代表原消息到达时刻。
“刚才、现在、今天、明天”等先按原始接收时间理解，再结合当前时间回复。
</busy_schedule_wake_context>
```

`merge_prefix` 和 `merge_suffix` 支持 `{start_time}`、`{end_time}`、`{received_start}`、`{received_end}`、`{processing_time}`、`{message_count}`。旧配置中的“以下是”只在渲染时转换为“这些是”，不会修改配置文件。

## 数据存储

- 日程数据：`schedule_data.json`
- 忙碌时段数据：`busy_periods.json`
- 消息队列：内存中存储，插件重启后清空

## 注意事项

1. 插件重启后，当天的日程数据会保留，但消息队列会清空
2. 动态调整功能会消耗额外的token，建议根据需要开启
3. 聊天保护功能确保对话模型回复期间及回复后不会突然进入睡眠状态
